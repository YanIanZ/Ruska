# RUKSA RELIC — Autonomous Digital Restoration Studio

**Status:** New product direction, proposal only. **Supersedes:** procurement reconciler and generic execution fabric as public positioning. **Hackathon track:** Blast Radius Zero. **Brand:** RUKSA / RELIC. **Tagline:** Bring Lost Software Back to Life.

## The problem
Schools, small organizations, community services and institutions continue to depend on aging web workflows whose source, tests or documentation are missing. Rebuilding a UI from a screenshot is not enough: users still need the original validation, transitions, intent and confirmed outcomes. Restoring a real production application demands ownership, authorizations and business domain review.

## Product thesis
RUKSA RELIC uses an AI browser archaeologist to explore an **operator-owned legacy application in a bounded sandbox**, capture observable behavior, mark unknown logic explicitly, generate a new accessible working interface in a separate execution sandbox, then compare the original and replacement using **the same synthetic user journeys**. Export the new source and executable parity tests for a human maintainer. No cutover without human review.

## Unique product primitives
1. **Behavior Genome:** evidence-backed state machine extracted from observed navigation, form fields, validation, transitions, accessibility tree and outcome contracts. Rules have OBSERVED / HYPOTHESIS / UNOBSERVABLE labels.
2. **Ghost Browser:** non-production, owned synthetic exploration; read-only where possible, use disposable fixture backend for submits. Every step is observed, never guessed into fact.
3. **Rebirth Compiler:** translates approved Genome into a modern accessible UI source project; executes generation/build/test code in an isolated Vultr sandbox. Do not copy third-party trademarks, prose or assets.
4. **Parity Arena:** old and new flows receive identical fixture inputs. Compare normalized output payload, validation behavior, and successful state transitions; disagreement remains visible and blocks "restored" status.
5. **Missing Knowledge Ledger:** unexplored states, unverifiable back-end behavior and contradictory evidence are shown as gaps requiring a human, not invented by AI.
6. **Revival Capsule:** export source, observed spec, test suite, migration notes, signed/unsigned evidence summary, and rollback instructions.

## Product user journey
Input an authorized legacy web flow (or the provided owned demo portal). AI explores it with Playwright inside Vultr isolation, learns a small workflow, presents a Behavior Genome, generates a modern replacement, builds it, and runs paired browser journeys. The operator can inspect source and download the capsule. No production deployment or external transactions in hackathon scope.

## Distinctive innovation claim
We do NOT claim to have invented app modernization, browser automation, AI coding, or accessibility repair. The point of difference is **behavioral archaeology + user-centered reconstruction + executable parity testing as the product itself**, with a visible ledger of what cannot be inferred.

## Customers and business
Beachhead: small public-serving institutions, schools, universities, nonprofits and SMEs dependent on old internal portals. Revenue possibility after hackathon: paid assessments per workflow, assisted migration packages, controlled enterprise deployments and reviewer workflows. Pricing, savings and demand are hypotheses until validated.

## Scope guardrails
The first demo is a **project-owned fictional community-service portal**. No unauthorized crawling, bypass of login or anti-bot, production writes, extraction of private customer data, or clone-and-publish of third-party branded applications. Do not claim parity outside tested journeys. Human migration sign-off required.

## Four proof moments for judges
1. The agent genuinely operates a legacy browser, and records observed behavior.
2. Vultr Inference actually generates a candidate replacement code artifact.
3. Code is really built/run in an isolated sandbox; Playwright verifies old/new on synthetic cases, showing precise pass/fail.
4. An intentionally unsafe/runaway generated build is terminated; production-like host/control plane remains healthy.
